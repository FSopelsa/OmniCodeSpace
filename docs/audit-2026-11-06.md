# Audit, 6 November 2026

A whole-repo review at `d34887d`, plus the uncommitted `OMNI_PROXY` change in `server/runs.ts`. The assumed load is one person on one PC, with a few browser tabs, a few dozen repos and a handful of agents at once.

`npm run check` is clean, and `npm test` passes all 75 tests. Reading every session log takes about 1 second the first time and 13 ms after that, so polling every 5 seconds is fine at this size.

**Verdict:** Healthy. Fix 1 first, then 3.

## Should fix

1. **The push gate only watches shell commands** (`server/runs.ts:60`, `server/gate.ts`). The hook matches only `Bash|PowerShell`. A GitHub MCP tool such as `push_files`, `create_or_update_file` or `merge_pull_request` never reaches it, so a run whose Claude Code rules allow those tools can change GitHub with no click.
   **Fix:** Widen the matcher to `Bash|PowerShell|mcp__.*`. In `gate.ts`, treat a tool whose name matches `/push|create_or_update_file|delete_file|merge|create_branch/` as a push, and send its name as the command. Add one case to `test/runs.test.ts`.
   **Done.**

2. **Any program on this PC can read the page's token** (`vite.config.ts`, `server/runs.ts:165`). `curl http://127.0.0.1:5173/` returns the token. A run allowed to use `curl` could fetch it and approve its own push through `/api/runs/answer`. The comment in `runs.ts` promises more than the code does.
   **Fix:** No small code change closes this. Correct the comment, and add one line to the README's guardrail paragraph saying that a program on this PC can read the token.
   **Done.**

3. **Two order checks at once can start two questions** (`server/orders.ts:181-184`). The "is a question already running?" check happens several `await`s before the run is recorded. Two tabs, or **Check now** clicked during the 60-second timer, can each start a different question at the same time.
   **Fix:** Add a module-level `asking` flag around the start, cleared in a `finally`. Add a test that calls `checkOrders` twice without awaiting.
   **Done.** The test showed a worse effect than two runs: the losing check marks the question as failed, the winning check then sees it as blocked, and the question doesn't run until the server restarts.

## Nice to have

4. **`CLAUDE_CONFIG_DIR` is honoured in one place only** (`server/sessions.ts:156` vs `:171`). Plan left follows the variable, but the session list always reads `~/.claude/projects`. With the variable set, Roster and Data show no Claude sessions.
   **Fix:** Use one `claudeHome` constant for both.

5. **The "push rejected" handling exists twice** (`server/orders.ts:34,169-170`, `server/todo.ts:99-100`).
   **Fix:** Move one `pushError(e)` helper into `server/git.ts` and call it from both files.
   **Done,** as `failure()` and `REJECTED` in `server/git.ts`.

- Remote URLs keep part of a password that contains an unencoded `@`.
