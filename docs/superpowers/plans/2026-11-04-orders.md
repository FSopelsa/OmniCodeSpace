# Orders and Questions over Git Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** A cloud agent pushes an order branch. This PC lists it under "Needs you", runs it in a worktree after your click, commits a `report.md`, and pushes the branch back after a second click. Read-only questions to another opted-in project start by themselves.

**Architecture:** A new `server/orders.ts` fetches and reads order branches with git and works out each order's state from the remote and local branch tips. It starts runs through `startRun`, which gains an existing-branch option, a separate working folder, read-only flags and an end-of-run callback that writes the report commit. Three token-protected API routes and a "Needs you" list in the Roster view sit on top.

**Tech Stack:** Node 24 (runs `.ts` directly), git CLI, React 19, Tailwind 4, `node:test`. No new dependencies.

**Spec:** `docs/superpowers/specs/2026-11-04-orders-design.md`. Read it first. This plan only adds the decisions the spec leaves open.

## Global Constraints

- **No staging or commits.** Leave every change uncommitted for review in IntelliJ (owner's CLAUDE.md). Where the skill template says "Commit", skip it.
- **Test commands:** `npm test` (all of `node --test test/*.test.ts`) and `npm run check` (`tsc --noEmit`). Both must pass at the end of every task.
- **No new dependencies.** No abstractions or options beyond what the tasks name.
- **Comments:** only the why, in one line. A known limit gets `// shortcut: <the limit>, <when to upgrade>`.
- **Branch name rule** (exact): `/^(omni\/orders|claude)(\/[A-Za-z0-9][A-Za-z0-9._-]*)+$/`
- **Trailers:** `Omni-To`, `Omni-Status`, `Omni-Ask`. Statuses are `open` (sender), and `done`, `failed` and `stopped` (this app). Run status maps as finished to done, failed to failed, stopped to stopped.
- **Timing:** the fetch runs at most every 5 minutes (`5 * 60_000`) unless `now`. The page posts a check every 60 seconds.
- **Text cap:** order text is cut at **18,000** characters, plus `\n\n(Cut short.)`. This deviates from the spec's 20,000, because `startRun` refuses tasks over 20,000 and the framing must fit. The agent's summary in `report.md` is cut at 20,000.
- **Prompt-free git for fetch and push:** run with env `GIT_TERMINAL_PROMPT=0` and `GCM_INTERACTIVE=never`, plus `-c core.fsmonitor=false`, the same as `git()`.
- **Fixed text:** use the spec's wording for the order and question framing and the AGENTS.md note. Use these error strings exactly:
  - `This order changed. Check for orders again.`
  - `This order is already running.`
  - `The branch moved on GitHub since this PC worked on it. Check for orders again.`

## Review Focus

1. **Login missing:** a repo whose `origin` can't be reached or needs a login must show a per-repo error, never hang or open a sign-in window, and the other repos' orders must still be listed. Pinned in Task 3, test `only repos with orders on are fetched…`.
2. **No `order.md`:** an order branch without the file is listed as **blocked** with a reason and can't be run. Pinned in Task 3, test `lists open orders…`, and Task 4, which checks that Run refuses it.
3. **Long order:** a 25,000-character `order.md` still runs. The text is cut and the task stays under `startRun`'s limit. Pinned in Task 4, test `a very long order still runs`.
4. **Double start:** Run clicked twice, or a question already started, must refuse the second start with `This order is already running.`, and no second worktree is made. Pinned in Task 4, test `running an order…`.
5. **Sender pushed again after the local run:** Send back is refused with the "moved on GitHub" message, the local report commit is kept, and the next check shows **diverged**. Pinned in Task 4, test `a rejected push…`.

- [ ] **Step 3: Implement in `server/orders.ts`**

**`runOrder`:**
1. Find the order with `listOrders(repo, ctx.repos)`.
   - If it's missing or not open, throw `This order changed. Check for orders again.`
   - If its state is **running**, throw `This order is already running.`
2. For a question, find the target repo: the entry in `ctx.repos` whose basename equals `ask`.
3. Call `startRun` with:
   - `{ tool, model, task, branch, order: { branch, ask } }`;
   - `from`: `refs/remotes/origin/<branch>`;
   - for a question, also `cwd: <target>` and `readOnly: true`;
   - `onEnd`: `report(repo, order)`.
4. The task is the spec's order or question framing, with the order's text between `---` lines.
5. Hold a module-level `starting` Set of `repo|branch` from the check until `startRun` returns, so two clicks in quick succession can't both pass the state check.

**`report(repo, order)` returns `async (run) => …`.** In `run.worktree` it:
1. writes `report.md` in the layout below;
2. runs `git add -A`;
3. runs `git commit -m 'Report for order <branch>' -m 'Omni-Status: <done|failed|stopped>\nAgent: OmniCodeSpace (<tool> run <id>)\nWhy: Send the result of this order back to its sender'`.

The summary is the text of the last `say` line, or `The agent said nothing.` The commits are `git log --format='%h %s' <run.base>..HEAD`, taken before the report commit, or `- None` when there are none.

```
# Report for <branch>

- Outcome: <status>
- Run by: <tool>[ (<model>)] on <os.hostname()>, <started> to <ended or now, ISO>

## Summary

<summary>

## Commits

- <sha> <subject>
```

**`sendOrder`:**
1. Check that the order's state is **ready**, else throw `This order changed. Check for orders again.`
2. Run `quiet(repo, 'push', 'origin', 'refs/heads/<branch>:refs/heads/<branch>')`.
3. If the error mentions `rejected`, `non-fast-forward` or `fetch first`, throw the "moved on GitHub" string. Otherwise throw git's message, trimmed.
4. Return `{ pushed: <local tip> }`.
